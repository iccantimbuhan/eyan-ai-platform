# Claude Code - Build Feature

You are implementing a new feature in this repository.

Follow the repository engineering standards exactly.

---

# Objective

Implement the requested feature while preserving the existing architecture, coding standards, and project consistency.

Never prioritize speed over quality.

---

# Step 1 — Understand the Feature

Before writing code:

Summarize the requested feature.

Identify:

- Business objective
- User impact
- Technical objective
- Acceptance criteria

Do not write code yet.

---

# Step 2 — Analyze the Existing Repository

Inspect the repository for:

- Existing services
- Existing controllers
- Existing repositories
- Existing DTOs
- Existing validators
- Existing components
- Existing hooks
- Existing utilities

Reuse existing patterns whenever possible.

Avoid duplicate implementations.

---

# Step 3 — Impact Analysis

Determine:

- Files to modify
- Files to create
- Database impact
- API impact
- Frontend impact
- Authentication impact
- Authorization impact
- Configuration impact
- Documentation impact

Explain any architectural implications.

---

# Step 4 — Implementation Plan

Produce a clear implementation plan.

Include:

1. Tasks
2. Files
3. Risks
4. Validation strategy
5. Testing strategy

If the implementation changes architecture or introduces a new pattern, stop and ask for approval before continuing.

Do not implement yet.

---

# Step 5 — Wait for Approval

Pause.

Wait until I approve the implementation plan.

---

# Step 6 — Implementation

After approval:

Implement incrementally.

Follow:

- Existing architecture
- Existing naming conventions
- Existing folder structure
- Existing coding standards

Do not modify unrelated files.

Prefer extending existing modules over creating new ones.

---

# Step 7 — Validation

Verify:

✓ Build

✓ Typecheck

✓ Lint

✓ Tests

If validation fails:

Explain the failure.

Do not ignore it.

---

# Step 8 — Self Review

Review the implementation.

Evaluate:

- Readability
- Maintainability
- Security
- Performance
- Scalability

Apply improvements if appropriate.

---

# Step 9 — Final Report

Return the following report.

## Feature Summary

## Files Created

## Files Modified

## Build Result

## Typecheck Result

## Lint Result

## Test Result

## Documentation Updated

## Risks

## Follow-up Recommendations

## Definition of Done

A feature is complete only after all required validation has been performed.
