# ADR-0016 — Presentation Engine Phase 2B: AI Content Studio as a Cinematic Product Story

## Context

Phase 2B's brief was explicit that the Presentation Engine Core (store, Scene Manager, Timeline Engine, Playback, Camera, Highlight, Animation Driver, Narration/Subtitle architecture, Presentation Overlay, Presentation Library, routing, Tour Pack architecture) is frozen and production-ready — only the AI Content Studio Tour Pack's content was in scope. The prior AI Content Studio presentation (Phase 2A) was a shallow, six-scene "project list + production dashboard" tour that never entered a real project workspace; it read as a navigation demo, not a product demonstration. This phase rewrites it into an 18-scene, single-story walkthrough of the full content-production lifecycle (Overview → Content → Images → Brand → Video → Assets → Review → Publishing → Analytics → Summary), narrated for business value rather than UI description. Three decisions here touch shared state or make real trade-offs; the engine itself was not modified anywhere.

## Decision 1: A real, seeded demo `ContentProject` ("Nimbus Coffee Co. — Spring Launch") backs the flagship tour, instead of an empty project

The brief required the tour to "actually demonstrate" the product — open real cards, show generated results, review states, and analytics — not merely navigate to empty states. A fresh project has no generated content, images, brand kit, or review/publishing history, so every deep scene would show a "no data yet" placeholder instead of the product working. `backend/prisma/seed-demo-content.ts` seeds one fully-populated `ContentProject` directly via Prisma (`seedDemoContentStudioProject()`, called from `seed.ts`), bypassing every real AI provider entirely — no generation call, no cost, no wall-clock wait, and fully idempotent (a second seed run is a no-op once the project exists). Generated images are real, viewable PNG files: a from-scratch PNG encoder (`makeSolidPng`, using only Node's built-in `zlib.deflateSync`, no image-processing dependency) writes solid-color placeholders to `backend/storage/images/<projectId>/` — the same path `LocalDiskStorageProvider` and the `/uploads/images` static route already serve, so these render through the real image pipeline, not a special case.

**Consequence**: this seed data is now a permanent part of `pnpm run db:seed`, not a one-off verification fixture. Anyone re-seeding a dev/demo database gets the same "Nimbus Coffee Co." project, brand kit, generated content/images, one video group (script + storyboard + thumbnail), a mixed review/publishing state (one item needing review, two approved, one revision-requested, one scheduled, one published), and matching analytics events — chosen specifically so the Review Queue, Publishing Queue, and Analytics charts all have real, non-trivial data to show.

## Decision 2: The demo account's `Viewer` role gains the `presentation-engine` permission, so it can launch the flagship tour directly

The new AI Content Studio Tour Pack routes into `/app/content-studio/$projectId` — the real project workspace — which only its owning user can view (`ContentProject` is single-owner, per ADR-0007). For the tour to show real data when launched, the demo account (`demo@eyanstudio.dev`) must both own the seeded project (it does — `seedDemoContentStudioProject` creates it under that user) and be able to reach the Presentation Library to start the pack. `backend/prisma/seed.ts`'s `viewerPermissionNames` gains `'presentation-engine'` alongside the Phase 2A grants (`dashboard`, `chat`, `models`, `conversations`). This is still a read-only capability — it only gates a launcher/library page — so it stays within the least-privilege posture ADR-0015 established for this publicly-documented account.

## Decision 3: A generic "click a real element" custom action — and an explicit non-solution for "press Escape"

The brief asked scenes to actually interact with the app (select a template, open a real asset) rather than just navigate and highlight. The engine's `custom` action escape hatch (unused until now) is exactly the designed seam for this: `content-studio.scenes.ts` registers one generic, reusable handler — `content-studio.click-target` — that resolves a `data-presentation-target` key and calls `.click()` on it, used to (a) select a real template card in the Content tab and (b) open a real asset via `AssetDetailSheet` in the Assets tab.

Closing that Sheet was initially implemented as a second custom action dispatching a synthetic `Escape` keydown on `document` — this broke the tour during verification: `use-presentation-keyboard-shortcuts.ts` (part of the frozen engine) also listens globally for `Escape` as its "exit tour" shortcut, so the synthetic keydown silently ended the entire presentation mid-scene, with no console error (the engine's error path only triggers on thrown exceptions, not on an intentional exit). Since the keyboard-shortcuts hook can't be touched, the fix was to close the Sheet the same way a real user would with the mouse: `<SheetPrimitive.Close>` in the shared `frontend/src/components/ui/sheet.tsx` primitive now carries `data-presentation-target='ui.sheet-close'` (one generic, reusable attribute on shared UI, not a content-studio-specific change), and the scene clicks that instead of simulating a keystroke.

**Consequence**: any future scene, in any module, that needs to close a Radix Sheet/Dialog live during a presentation should click its real close control via `content-studio.click-target` (or a module-equivalent), never dispatch a synthetic `Escape` — doing so will always race the engine's own global exit shortcut.

## Consequences

- `frontend/src/features/presentation-engine/scenes/content-studio.scenes.ts` now has 21 scenes total (6 shared/overview scenes reused by Recruiter/Customer Tour unchanged, plus 15 new deep-dive workspace scenes); `ai-content-studio-tour.ts` curates 18 of them into the flagship story. Recruiter/Customer Tour packs were not modified and still resolve every scene reference (verified by the existing "zero dangling scene references" test).
- 13 new `data-presentation-target` attributes were added across real Content Studio workspace components (`GenerateForm`, `TemplateCard`, `GenerationHistory`, `ImageGenerateForm`, `ImageOutputViewer`, `BrandKitCard`, `VideoGenerateForm`, `VideoAssetList`, `AssetLibrary`, `AssetCard`, `ReviewQueue`, `PublishingQueue`, `AnalyticsSummary`, `ProjectWorkspace`) — all one-line additive changes, no component logic touched.
- Future Tour Packs that need "click a real element" should reuse the `content-studio.click-target` pattern rather than inventing a new custom action per module.
